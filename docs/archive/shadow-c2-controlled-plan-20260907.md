## 1. 실행보다 먼저 통과해야 하는 정확성 조건

기존 C2는 실제 검색 원문의 넓은 인용문 안에서 다른 과정의 일정과 다른 상담실의
전화번호를 잘못 연결해도 허용한다. 두 합성 반례를 발견했으므로, 현재 버전으로
대량 생성해 점수만 비교하는 작업은 우선 보류한다.

1. 수정 권한을 별도로 받은 **새 실험 버전**에서 일반적인 주체–관계–값 결속을
   설계한다. C1, 동결 C2, Judge, gold는 수정하지 않는다. DEV/Shadow ID별 예외 금지.
2. 현재 합성 검사 6개 모두 원문 기준 기대와 일치해야 한다. 오허용 0뿐 아니라
   올바른 주장 2개 보존도 필수다. 지금 characterization 테스트가 통과해도 이 gate는 실패 상태다.
3. 회귀 범위는 날짜/전화 외 금액·모집인원·연도·부정·의무·조건까지 확장한다.
   주체 이름·표 행 순서·값을 바꾼 합성 대조와 제목/본문 경계도 검사한다.
   이를 끝내도 실제 생성 품질을 증명한 것으로 보지 않는다.
4. 이미 살펴본 Shadow60은 이후 실험에서 개발 진단용임을 명시한다.
   새 규칙의 독립 검증을 했다고 주장하지 않는다. 최종 검증은 아직 열지 않은
   holdout과 사람 calibration 절차를 따른다.

## 2. 비교가 답하는 질문

주 질문은 “동일하게 저장된 검색 근거를 사용하는 **생성·검증 패키지** 교체가
질문 단위 정답성을 높이는가?”다. **quote 결속만의 단일 요인 효과**라고 부르지 않는다.

오프라인 프롬프트 구성으로 확인한 현재 조건 차이:

| 항목 | 저장 C1 | 현재 C2 계획 |
|---|---|---|
| 근거 | 각 run의 final context와 순서 | 같은 run의 동일 context와 순서 재사용 |
| 근거 전체 본문 보임 | 각 run 42/42 | 각 run 42/42 |
| 근거 렌더링 | Institution/File/Section 형식 | Title/Section 형식; 근거 블록 바이트 동일 0/42 |
| 출력 token 상한 | 900 | 1,200 |
| temperature | 저장 요청에 미지정 | 0.0 |
| 생성 형식 | 자연어 초안+후처리 | 구조화 claim·quote+검증 |
| 수집 시점 | 9월 5일 기존 수집 | 실행 승인 뒤 별도 시점 |

C2 최대 프롬프트는 **11,416문자**, 전체 126개 계획에서 원래 context 본문은
잘리지 않았다. 그러나 본문이 같다고 메타데이터·명령·출력 예산까지 같지는 않다.
미지정 temperature의 실제 숫자 기본값은 추정하지 않는다. 모델 별칭이 같아도
수집 시점 차이로 백엔드가 같음을 보장하지 못하므로 반환 모델 버전도 기록한다.

단일 요인 인과 주장이 필요하면 승인받아 C1/C2를 같은 시점·예산·temperature·
동일 근거 렌더링으로 새로 수집해야 한다. 아래 252회 예산에는 이 추가 대조군이 없다.

## 3. 표본·분석 규약 초안

- 대상은 이미 정한 `simple 24 + multi 18 = core42` **전체**다. 실패 11개나
  진단 14개만 뽑아 headline을 만들지 않는다. 각 run의 저장 근거를 그대로 사용한다.
- 독립 생성 3회, 주지표는 질문별 **2/3 majority GFC**. 평균 0–2점은 보조 지표다.
  생성 126개를 독립 질문 126개인 것처럼 CI를 계산하지 않는다.
- C1/C2를 질문 ID로 짝짓고 현재 v11 rubric/guard를 동일하게 사용한다.
  기존 점수는 보존한다. 사람 검토를 대신한 AI 교정 점수는 만들지 않는다.
- 양쪽 모두 완결된 경우에 질문 단위 paired delta와 95% bootstrap CI,
  exact McNemar를 보고한다. 가족 ID 정의를 결과 전에 고정할 수 있는 경우
  family-cluster CI도 병기한다. CI가 0을 포함하면 개선 확정 표현을 쓰지 않는다.
- 부차 지표는 지원되지 않는 사실·모순·필수 claim 누락·과잉 회피·인용 오류,
  run별 GFC, p50/p95 지연, token 사용량, 재시도/형식 실패다.
  지연 비교는 저장 C1 수집 환경 차이를 함께 밝혀 순수 코드 속도 개선으로 해석하지 않는다.
- 생성이나 Judge가 종료 실패하면 같은 slot을 사전 지정 재시도 한도 안에서만
  재시도한다. 성공 답변만 골라 분모를 줄이지 않는다. core126 중 미완결이 남으면
  headline을 확정하지 않고 slot별 누락표·실행 실패율과 계획 대비 완결성을 보고한다.
- 모델 가용성·쿼터 때문에 다른 모델로 바꿔야 하면 중단 후 새 조건으로 분리한다.
  한 조건에 서로 다른 모델 출력을 섞지 않는다. resume 시 sleep 등 config를 바꾸지 않는다.
- 실행 도중 결과를 보고 튜닝하거나 성공 답변을 선택하지 않는다. 실험 코드·cases·
  context·모델/요청·Judge config·실행계획 SHA를 수집 전에 새 경로에 고정한다.

이 문서는 **실행 전 합의안 초안**이다. 반례 수정 및 위 조건 핀을 마치기 전
사전등록 완료라고 표현하지 않는다. 현재 결과를 확인한 Shadow를 확증용으로 되돌리지 않는다.
