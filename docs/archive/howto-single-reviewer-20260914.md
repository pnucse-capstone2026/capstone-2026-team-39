# How to: 사람 1인 검수 후 LLM Judge와 비교하기

[1인 평가 개정안](evaluation-amendment-single-reviewer-20260914.md)에 따라
원문을 보고 먼저 채점하고, 저장한 최초 판정과 Judge의 일치도를 비교한다.
**현재는 안내 문서이며 새 1인 검수 화면이나 실제 평가 결과가 준비됐다는 뜻은 아니다.**

## 시작 전 준비

- 질문·정답지 36문항의 1인 원문 검수와 코드·데이터 동결을 마친다.
- 승인된 평가 실행 후 기존 계획의 답변 63개(Core C0/C1 54개, Challenge C1 9개)를 선택한다.
- 실제 검수자 이름/ID 하나를 사용한다. 두 번째 검수자나 합의 라벨은 만들지 않는다.
- 조건명과 Judge 결과를 숨긴 검수 화면, 질문·필수 주장·원문·검색 문맥·답변·인용을 준비한다.
- DEV 답변 8개로 기준을 연습한다. 연습 표본은 본평가 일치도에 포함하지 않는다.

## 채점 순서

1. **질문이 요구한 내용을 확인한다.** 연도, 대상 사업, 신청 대상, 금액·기한·예외 조건을 구분한다.
2. **답변과 실제 근거를 대조한다.** 정답과 비슷한지만 보지 말고 각 사실을 인용한 문서가 실제로 뒷받침하는지 확인한다.
3. **0~2점을 선택한다.** 완전하고 정확하면 2, 부분 누락·오류가 있으면 1, 결론 오류·중대한 근거 없음·부적절한 회피이면 0이다.
4. **GFC 통과/실패를 별도로 선택한다.** 2점이며 필요한 내용이 모두 있고 사실과 인용이 검색 문맥으로 지지될 때만 통과다. 2점과 GFC는 같은 필드가 아니다.
5. **불확실하면 표시하고 이유를 남긴다.** 예: “본문에는 지급 시점이 없고 제목만 있어 판단 보류”. 자동으로 오답 처리하거나 근거 없이 확신하지 않는다. Challenge는 적절한 회피·공격 지시 이행 여부도 표시한다.
6. **저장 확인 후 다음 답변으로 이동한다.** 모든 최초 라벨을 확정한 뒤에만 Judge 결과를 공개한다.

## 저장 검증: 답변 유실 방지

새 화면 구현 시 아래 조건을 모두 검증한 뒤 실제 검수를 시작한다.

- 브라우저 localStorage나 다운로드 버튼만 믿지 않고 로컬 서버의 디스크 저장을 사용한다.
- 저장마다 revision, 저장 시각, SHA-256과 서버 재조회 결과를 표시한다. 실패했으면 “저장 완료”라고 표시하지 않는다.
- 연습 항목을 입력하고 새로고침·탭 닫기·서버 재시작 후 같은 내용이 복원되는지 확인한다.
- 수정 이력과 별도 JSON 백업을 보존하고 두 탭에서 오래된 내용이 최신 내용을 덮어쓰지 못하도록 한다.
- Judge 공개 전 확정본을 별도 보존한다. 공개 후 수정하더라도 최초 라벨과 노출 이력을 지우지 않는다.

기존 [Shadow 검수 저장 서버](../../evidence/review-durable-20260909-v1/server.py)는
revision·SQLite·백업을 사용하는 참고 구현이다. 새 1인 GFC 라벨에 그대로
호환된다고 확인한 것은 아니므로 기존 화면을 최종 검수용이라고 안내하지 않는다.

## 완료 확인

Core 54개와 Challenge 9개에서 미작성 항목, 저장 오류, 답변 ID/SHA 연결 오류를
각각 확인한다. 실제 완료 수를 공개하고 일부만 끝났으면 부분 결과로 표시한다.
본인이 불확실로 표시한 항목 수와 Judge를 미리 본 항목 수도 따로 남긴다.

최종 비교 화면은 다음을 분리해서 보여준다.

- GFC 통과/실패 일치율: 일치 건수 / 비교 가능 건수, 백분율.
- Cohen's κ와 클래스 불균형 보조 지표.
- 0~2점 정확 일치율과 점수 차이를 반영한 weighted κ.
- 사람 실패/Judge 통과, 사람 통과/Judge 실패 목록과 원문 근거.

## 문제가 생기면

- **저장 실패:** 현재 입력을 별도 복사해 보존하고 저장·재조회가 성공할 때까지 다음 항목으로 넘어가지 않는다.
- **Judge를 먼저 봄:** 노출 사실을 표시한다. 다시 가린 뒤 독립 판정이었다고 처리하지 않는다.
- **정답지 오류 발견:** 원문과 오류 사유를 기록한다. 최종 실행 뒤에는 정답지나 기존 결과를 덮어쓰지 않고 별도 정정 분석으로 남긴다.
- **Judge와 의견이 다름:** 최초 판정을 고쳐 일치율을 높이지 않는다. 사후 원문 검토 결과를 별도 기록한다.
- **기존 도구가 검수자 부족 오류를 냄:** 2인용 도구에 1인 결과를 넣은 상태다. 라벨을 복제하지 말고 새 1인 분석 경로를 사용한다. 현재 그 경로는 구현 전이다.

판정 원칙과 지표의 정확한 정의는 [개정안](evaluation-amendment-single-reviewer-20260914.md)을 따른다.
