- 승인 파일 SHA, 실행 제안 SHA, 고정 run 경로, 모델/slot/상한을 확인한다.
  단일 키·모델 고정 조건을 벗어난 승인 명세는 거부한다.
- 실제 호출 전, 같은 실행기 소스 SHA로 통과한 로컬 검증과 산출물 해시가 필요하다.
  새 실측 장부는 승인된 고정 경로 하나에서만 생성한다. 기존 파일을 덮어쓰지 않는다.
- 키는 승인 검증 뒤 기존 Gemini 환경변수 또는 프로젝트 `.env`에서 하나만 선택한다.
  키 값은 로그/명령 인자/장부에 기록하지 않는다. 서버 자식에는 private stdin pipe로
  보내며 Popen 환경에 넣지 않는다. 자식 내부에서만 기존 생성기가 읽는 환경에 연결한다.
- 자식 서버는 임시 loopback 포트 하나만 연다. PID/nonce/private pipe/실제 bind,
  health·전체 사본·인덱스·source manifest를 대조하고 기존 collector로 수집한다.
- 별도 생존 확인 pipe가 끊기면 자식 자신만 종료한다. 정상 종료/오류 때도 실행기가
  소유한 프로세스만 정리한다. 불확실한 provider 예약은 자동 환급하지 않는다.
- 생성과 Judge의 실제 HTTP 전송 전에 같은 SQLite 장부에 예약한다. 실제 provider
  backend는 고정 Gemini HTTPS endpoint만 허용하고 환경 proxy/redirect를 사용하지 않는다.
- 이전 완료 slot은 엄격한 검증 후 건너뛴다. 미완료 slot은 자동 재생성하지 않고
  수동 확인 대상으로 멈춘다. 기존 답변/Judge 파일과 설정을 덮어쓰지 않는다.

## 하루 500회 조건에 대한 보수적 제어

**이 실행기는 이 run의 호출만 볼 수 있다. 다른 앱·기존 실행의 오늘 사용량은 모른다.**
따라서 전체 프로젝트 사용량이 반드시 500회 미만이라고 보장하지 않는다.

1. 프로젝트 한도 500회를 사용자 제공 제약으로 기록하고, 이번 작업은 태평양 시간
   날짜별 **450회**를 보수적 중단 기준으로 둔다. 다른 키/모델로 자동 전환하지 않는다.
2. 다음 slot의 최대 재시도까지 450회 안에 들어갈 때만 시작한다. 완료12 slot 이후에는
   관측된 평균 시도 수로 남은 호출을 추정하고, 예상 총량이 450회를 넘으면 시작 전에 멈춘다.
   이것은 예측치이지 남은 호출의 보장이 아니다.
3. 전송 간격은 최소15초로 별도 제한한다. 기존 collector/Judge의 sleep3·재시도 인자와
   prompt는 유지했다. 실제 RPM/TPM 한도는 미확인이고 지연 성능 비교에 사용하지 않는다.
4. 첫 401/403/404/429 응답이면 중단 표식을 남겨 후속 provider 전송을 차단한다.
   429가 RPM/TPM/RPD 중 무엇인지 추측해 자동 키 교체나 무한 재시도하지 않는다.
5. 전체 실험 상한918 및 생성 최대3/Judge 최대6도 동시에 적용한다. 정상 진행 시 약204회,
   보안상 생성 생략이면 더 적다. 918회는 최악 재시도 상한이고 무료 사용 보장이 아니다.

할당량은 API 키가 아니라 프로젝트 기준이며 모델별 한도가 다를 수 있다. 일일 한도는
태평양 시간 자정에 재설정된다. 실제 적용값은 AI Studio에서 확인해야 한다.
