# Shadow14 원문 기반 AI 진단 — 2026-09-07

## 결론과 범위

검색된 필수 근거가 모두 있는데 majority 비GFC였던 **11문항 중 9문항에서
맞는 초안 정보가 후처리 또는 문장 분리 단계에서 손실되는 경로를 확인했다.**
나머지 2문항은 Judge의 인용문 작성 오류가 점수 강등에 직접 영향을 주었다.
따라서 이 부분집합에서는 검색 규칙 추가보다 근거 검증·문장 분리·평가 계약을
분리해서 다루는 것이 우선이다. 9문항의 모든 초안이 완벽하다는 뜻은 아니다.

다만 대안 C2도 그대로 채택하면 안 된다. 실제 검색 원문에 **의도적으로 만든
오답**을 넣은 검사에서 다른 과정의 날짜와 다른 상담실의 전화번호가 통과했다.
검증기의 정확한 인용 존재 확인은 주체–값 관계가 옳다는 보장이 아니었다.

분석은 위 11문항과 목적 선정한 성공 대조 3문항의 저장 답변 42개를 대상으로
했다. AI 진단이며 사람 검토·독립 calibration·새 성능 평가가 아니다.
Shadow core의 정본 **majority GFC 15/42 (35.7%), 보조 평균 1.1111**은
변경하지 않았다.[^score] 외부 호출 0회, 실제 holdout 접근 0회,
사람 판정 입력 0건이며 동결 서비스·C2·Judge 코드도 변경하지 않았다.

## 3. 동결 후 발견: 재현 가능한 실패 경로

### 3.1 거부 개수만으로는 잡히지 않는 날짜 손실

`shadow_emp_03` run1의 정제 초안
`활동기간은 ’26. 4. ~ ’27. 2.입니다.`가 문장 분리 뒤 `활동기간은 ’26.`으로
잘렸다. 해당 조각은 검증을 통과한다. 즉, 최종 거부 개수 0을 정보 보존으로
해석하면 안 된다. 완전한 연월일을 보호하는 기존 날짜 처리와 달리 축약 연월
범위는 충분히 보호되지 않는다.

위치: [split_candidate_sentences](../../scripts/search_api.py#L1747),
[split_draft_claims](../../scripts/search_api.py#L7082).
이 발견은 7.4장의 기존 DEV 수정이 모든 날짜 표현을 해결했다는 뜻이 아님을 보인다.

`shadow_adm_06` run1은 `2026 12.7.` 형식의 연도를 놓친 뒤 다른 일정의
2027년을 가져와 `date:2027-12-07`, `date:2027-12-11`을 만든다.
원문 접수 일정은 2026년 12월이다. 여러 일정·연도가 섞인 문장에서 날짜 값이
올바른 사건과 결합되지 않는 경로다.
위치: [extract_critical_values](../../scripts/search_api.py#L4133).

### 3.2 맞는 기간의 관계 판정 실패와 제목 정보의 범위

신청 마감·국가근로 신청기간·GSAT 운영기간은 원문과 숫자가 맞는데도
`semantic_relation_mismatch`로 거부된다. 이는 확인된 개별 실패이지 관계 검사를
통째로 해제하라는 근거가 아니다.
위치: [_semantic_relation_mismatch](../../scripts/search_api.py#L6525).

아이디어 경진대회의 **제7회**, 논문 공모전의 **제21회**는 검색된 문서 제목에
있다. 본문에만 있는 접수기간·자격과 결합한 주장은 각각 `quantity:7:회`,
`quantity:21:회`를 찾지 못해 거부된다. 현재 제목 범위 상속은 연도·학기·
`round:`만 허용하며 이 값들은 `quantity:`로 추출된다.
위치: [_critical_value_support](../../scripts/search_api.py#L6768).
제목 값을 무조건 허용하면 다른 행·다른 문서 값까지 오결합할 수 있어 별도 검증이 필요하다.

### 3.3 최상위 거부 사유는 모든 검색 원문에 대한 판정이 아니다

`shadow_sup_04`의 전화번호가 없다는 최상위 `critical_value_mismatch`만 보면
코퍼스 누락으로 오인하기 쉽다. 실제 gold 근거에는 두 전화번호가 있다.
해당 근거만으로 재검증하면 숫자는 모두 충족되고 관계 위반도 없지만, 단어 중첩
점수 약 0.333이 기준 0.40보다 낮아 `low_lexical_overlap`로 실패한다.
최상위 누락 값은 다른 후보의 선택 결과에서 온다.
위치: [attribute_claim](../../scripts/search_api.py#L6924), 특히 `best_missing_values` 선택.
앞으로 원인 분석은 후보별 검증 사유와 원문을 함께 봐야 한다.

### 3.4 Judge 출력 오류와 guard의 역할을 구분

`shadow_emp_01` 3개 답변에서 지원액·제외 대상·통보일·지급일은 존재한다.
Judge는 지원액 문장과 떨어진 통보·지급 문장을 이어붙인 인용을 만들었다.
각 문장은 실제 답변에 있지만 결합한 문자열은 연속 구간이 아니다.

`shadow_adm_05` run1/3은 답변의 `운전면허증`을 Judge가 `운전메허증`으로
잘못 복사했다. 두 경우 모두 v11 guard는 정해진 계약대로 강등했다.
문제의 발생 단계는 Judge의 인용 작성이며, guard 자체를 오류로 단정하지 않는다.
위치: [_quote_is_contiguous](../../scripts/judge_service_answers.py#L920),
[apply_deterministic_judge_guards](../../scripts/judge_service_answers.py#L933).

분석기는 원래 판정과 guard 이후 판정을 나란히 기록할 뿐 점수를 복구하지 않는다.
특히 gold 범위 문제까지 함께 있는 문항에 원래 Judge 2점을 정답으로 대신 부여하면 안 된다.

## 4. C2 채택을 막는 합성 반례

검사 입력은 실제 모델 생성물이 아니라 **AI가 의도적으로 구성한 올바른 주장과
틀린 주장**이다. 인용문은 모두 실제 저장 원문의 연속 구간이며 길이 제한 안에 있다.

| 주장 | 인용 범위 | 원문 기준 기대 | 동결 C2 결과 |
|---|---|---|---|
| GSAT 운영 8월 5~7일 | 여러 과정 표 전체 | 허용 | 허용 |
| GSAT 운영 8월 24~28일 — 실제 NCS 일정 | 표 전체 | 거부 | **오허용** |
| 같은 틀린 GSAT 일정 | GSAT 행만 | 거부 | 거부 |
| 성평등상담실 051-510-7890 | 두 상담실 전체 | 허용 | 허용 |
| 성평등상담실 051-510-7942 — 실제 인권상담실 번호 | 두 상담실 전체 | 거부 | **오허용** |
| 같은 틀린 상담실 번호 | 성평등상담실 행만 | 거부 | 거부 |

위치: C2 [_verify_claim](../../scripts/rag/grounded_claims_v2.py#L490)의 인용 값·
anchor 검사. 넓은 인용문 안에 이름과 숫자가 따로 존재해도 주체–값 대응이
틀릴 수 있다. **6개 중 2개 오허용은 검증기 반례 수이지 C2 생성 오류율이 아니다.**

정본: [c2-verifier-probes.json](../../processed/eval/preflight-20260907/shadow14-ai-diagnostics-v1/c2-verifier-probes.json).
추가 테스트에는 이 결함의 현재 동작을 보존하는 characterization 검사가 있다.
**테스트 통과는 결함 재현 성공이지 C2 안전성 통과가 아니다.** 동결 코드 수정은 하지 않았다.

기계 재현은 완료했지만 다음 세 문항의 평가 범위는 AI가 임의로 확정하지 않았다.

- `shadow_adm_05`: 질문하지 않은 수험표와 신분증 확인서의 사진 부착 조건을 어디까지 필수로 요구할지.

일이 세 답변이면 끝난다는 뜻은 아니다. 기존 gold·Judge·사람 판정란은 유지한다.
